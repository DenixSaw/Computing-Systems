# Master–Slave: распределённый тройной интеграл (Симпсон), Python + PyQt6

Кросс-платформенное (Windows / Linux / macOS) десктопное приложение. Тройной интеграл по
параллелепипеду считается составной кубатурной формулой Симпсона на сетке N×N×N, а расчёт
распределяется между компьютерами локальной сети по схеме **Master–Slave**.

## Как делится задача

* Сумма Симпсона раскладывается по слоям X: `I = (hx·hy·hz/27) · Σ_i w_i · S_i`, где `S_i` —
  взвешенная сумма по (y, z) в слое `x_i`, а `w_i` — веса 1, 4, 2, 4, …, 4, 1.
* При нажатии «Запустить расчёт» master делит слои `0..N` на **непрерывные непересекающиеся
  диапазоны** между всеми узлами, **включая себя** (узел 0). Доля пропорциональна весу узла:
  числу ядер или поровну, в зависимости от режима «по числу ядер / равномерно». Границы
  выровнены по панелям Симпсона (чётные индексы), каждый узел берёт **глобальные** веса своих
  слоёв, поэтому сумма долей в точности равна последовательному расчёту без поправок на стыках.
* Каждому slave уходит **одно** сообщение `TASK` (диапазон + параметры). Сразу после рассылки
  master начинает считать свою долю в собственном пуле процессов, параллельно со slave.
* Каждый узел загружает все свои ядра через `multiprocessing.Pool`: слои режутся на порции,
  NumPy векторизует расчёт по порции слоёв, весь массив N³ в памяти не хранится.
* Slave присылает частичную сумму и время расчёта (`RESULT`). Master складывает все доли
  (`math.fsum`) и показывает итог.
* Если slave отключился или молчит дольше 15 с, master **сам пересчитывает его долю** и пишет
  предупреждение в журнал. Такой запуск получает `status = recovered` и не попадает на графики
  серии, потому что его время не отражает реальную конфигурацию.

## Структура

```
common/   protocol.py (длина + JSON), integrator.py (Симпсон, деление, пул процессов),
          discovery.py (UDP DISCOVER/ANNOUNCE), config.py (порты, таймауты, N), qt_utils.py
master/   server.py (TCP-сервер, RunWorker), results_store.py (CSV), plots.py (графики), gui_master.py
slave/    client.py (подключение и расчёт), gui_slave.py
tests/    юнит-тесты интегратора, протокола, CSV и графиков
main.py   стартовое окно «Запустить как Master / Slave»
runs/     создаётся автоматически: CSV, графики
```

## Установка

Нужен Python 3.10+.

```bash
python -m venv .venv
# Windows:            .venv\Scripts\activate
# Linux / macOS:      source .venv/bin/activate
pip install -r requirements.txt
```

> **Windows + Anaconda/Miniconda.** Не создавайте venv от conda-интерпретатора. Conda-Python
> подмешивает в поиск DLL свою папку `Library\bin`, и PyQt6 из pip падает с ошибкой
> `DLL load failed while importing QtCore: Не найдена указанная процедура`, потому что
> подхватывается чужой `icuuc.dll`. Используйте Python с python.org (`py -3.13 -m venv .venv`)
> или ставьте PyQt именно через conda.

Тесты:

```bash
python -m unittest discover -s tests -t . -v
```

## Запуск

```bash
python main.py
```

Откроется стартовое окно с кнопками **«Запустить как Master»** и **«Запустить как Slave»**.
Роль выбирается один раз; чтобы сменить роль, закройте приложение и запустите его заново.

### На четырёх компьютерах (целевой сценарий)

1. Все компьютеры должны быть в одной локальной сети (лучше по кабелю или Wi-Fi без изоляции клиентов).
2. **Откройте порты в файрволе** на компьютере master: **TCP 5000** (подключение slave) и
   **UDP 5001** (автопоиск). На Windows при первом запуске появится окно «Брандмауэр Защитника
   Windows» — разрешите доступ для частных сетей. Вручную (PowerShell от администратора):
   ```powershell
   New-NetFirewallRule -DisplayName "MasterSlave TCP" -Direction Inbound -Protocol TCP -LocalPort 5000 -Action Allow
   New-NetFirewallRule -DisplayName "MasterSlave UDP" -Direction Inbound -Protocol UDP -LocalPort 5001 -Action Allow
   ```
   Linux (ufw): `sudo ufw allow 5000/tcp && sudo ufw allow 5001/udp`.
3. На одном компьютере выберите **Master**. В блоке «Сеть» окна указаны IP master и все его
   адреса. Узнать IP можно и вручную: `ipconfig` (Windows) или `ip addr` / `ifconfig` (Linux/macOS).
4. На трёх других выберите **Slave**. Окно Slave сразу ищет master. Если найден ровно один и
   стоит галочка «Подключаться автоматически…», slave подключится сам. Если найдено несколько,
   выберите нужный в списке и нажмите «Подключиться к выбранному» (или дважды щёлкните по строке).
5. Убедитесь, что в таблице «Узлы» master видит всех slave (имя, IP, ядра). Затем нажмите
   **«Запустить расчёт»**.

### Как работает автопоиск и что делать, если master не найден

* Slave шлёт UDP-запрос `DISCOVER` (версия протокола и код группы) три раза с паузой. Адресаты:
  `255.255.255.255`, широковещательный адрес `x.y.z.255` каждого локального интерфейса
  (Wi-Fi, Ethernet, VPN…) и `127.0.0.1`. Ответы собираются ~2.5 с.
* Master слушает UDP-порт 5001 и отвечает **только на запросы со своим кодом группы**:
  unicast-сообщение `ANNOUNCE` с именем, IP, TCP-портом и числом подключённых slave. Ответы
  одного master через разные интерфейсы slave объединяет в одну строку.
* **Код группы** (по умолчанию `lab`) задайте одинаковым в master и своих slave, если в
  аудитории работает несколько групп, чтобы не подключиться к чужому master.
* Если master не найден (UDP-broadcast часто блокируют Wi-Fi с изоляцией клиентов, роутеры и
  файрволы), окно покажет подсказку. Тогда:
  1. проверьте, что компьютеры в одной сети и на master разрешён UDP 5001;
  2. введите **IP master и порт вручную** в блоке «Ручное подключение» и нажмите «Подключиться».
     Для этого достаточно открытого TCP 5000.
* Если UDP-порт на master занят, master не падает: в журнале появится сообщение, а ручное
  подключение по TCP продолжит работать.

### На одной машине

Запустите `python main.py` несколько раз: один экземпляр как Master и один-три как Slave.
Slave найдёт master через `127.0.0.1` или локальный адрес. Чтобы экземпляры не боролись за
ядра, разделите их полем «Процессов для расчёта»: например, на 8-ядерном ПК master 2 + три
slave по 2. Ускорения на одной машине не будет (ядра те же), этот режим нужен для проверки
работы.

## Параметры и выбор N

* Функции: **тестовая** `sin(x)·cos(y)·exp(z)` с точным ответом
  `(cos ax − cos bx)(sin by − sin ay)(e^bz − e^az)`: показываются абсолютная и относительная
  погрешность. **Тяжёлая** `sin(xy)·e^(−z) + √(x²+y²+z²+1)·cos(x+yz) + ln(1+xyz)` на
  неотрицательной области (по умолчанию `[0,2]³`).
* Время растёт как N³, тяжёлая функция стоит ≈ 70 нс на точку на одном ядре.
  * **Быстрый тест:** N = 200 (доли секунды).
  * **Демонстрация:** N = 1200 (≈ 2 мин на одном ядре). Master с 8 ядрами считает это за
    ~15–20 с, а 4 компьютера — в несколько раз быстрее.
  * Для более длинных замеров: N = 1600–2000.

## Итоги и замеры

После каждого расчёта master показывает:

* **Интеграл** и **общее время** (wall-clock: от нажатия «Запустить» до сборки суммы), а для
  тестовой функции ещё и погрешности;
* строку параметров: число узлов, всего ядер, функция, N, режим деления, серия, статус;
* **таблицу по узлам**: имя, IP, ядра, диапазон слоёв, доля в %, **время расчёта узла**
  (замеряется на самом узле, только вычисления, без сети) и частичная сумма. Master — обычная
  строка таблицы (выделена жирным).

Как читать таблицу: при хорошем балансе времена узлов близки друг к другу. Если один узел
заметно медленнее, переключите деление «по числу ядер» ↔ «равномерно» или проверьте нагрузку
на этом компьютере. Общее время ≈ максимум из времён узлов + сеть и сборка.

### Серии и сравнение конфигураций

Поле **«Название серии»** заполняется автоматически (`функция_N<N>_<режим>`, например
`heavy_N1200_cores`), пока вы не измените его вручную (кнопка ↺ возвращает автоназвание).
Порядок замеров для отчёта: запустить расчёт только на master (1 узел), подключить 1 slave и
запустить, затем 2, затем 3 slave. Все запуски одной серии попадают на одни графики.

## Где лежат CSV и графики (`runs/`)

Папка `runs/` создаётся рядом с `main.py`; другую можно выбрать кнопкой «Изменить…».
Кнопка «Открыть папку с результатами» открывает её в проводнике.

* `runs/runs.csv`: одна строка на запуск (`run_id, timestamp, function, N, split_mode, series,
  nodes_count, nodes_list, total_cores, total_time_s, integral_value, abs_error, rel_error, status`).
* `runs/run_nodes.csv`: одна строка на узел в запуске (`run_id, node_name, ip, cores,
  slice_start, slice_end, share_percent, node_time_s, partial_sum, is_master`).
* `runs/series_<серия>/` — перестраивается после каждого запуска серии:
  * `time_vs_nodes.png`: время от числа узлов;
  * `speedup_vs_nodes.png`: ускорение `S(n) = T(1)/T(n)` и идеальная линия `S = n`;
  * `efficiency_vs_nodes.png`: эффективность `E(n) = S(n)/n`;
  * `summary.csv`: по строке на число узлов (`nodes_count, run_id, nodes_list, total_cores,
    total_time_s, speedup, efficiency`);
  * `run_<id>/nodes_time.png`: время каждого узла в запуске (master выделен цветом).

Правила: CSV только дописываются, ничего не удаляется. На графики идут запуски со
`status = ok`, по одному **последнему** на каждое число узлов, так что повторный запуск с тем
же числом узлов заменяет точку на графике. Для ускорения и эффективности нужен запуск на одном
узле (только master), иначе в журнале будет подсказка. Если `runs.csv` открыт в Excel и
недоступен для записи, запуск сохраняется в `runs_<время>.csv` и учитывается при нумерации и
графиках.

Чтение в pandas:

```python
import pandas as pd
runs = pd.read_csv("runs/runs.csv")
nodes = pd.read_csv("runs/run_nodes.csv")
df = nodes.merge(runs, on="run_id")
```

## Протокол

TCP: кадр = 4 байта длины (big-endian) + JSON в UTF-8. Сообщения:

* `REGISTER`: slave → master (имя, ядра) и master → slave (подтверждение, итоговое имя узла);
* `TASK`: диапазон слоёв, N, границы, функция;
* `PROGRESS`, `RESULT` (частичная сумма, время узла);
* `HEARTBEAT`: раз в 2 с в обе стороны;
* `SHUTDOWN`: `reason=cancel` — остановить расчёт, `reason=exit` — master закрывается.

UDP 5001: `DISCOVER` / `ANNOUNCE`.
