## Роль

Ты опытный Python-разработчик, специалист по распределённым вычислениям и PyQt. Пишешь чистый, хорошо структурированный, рабочий код с понятными комментариями на русском языке. Код должен запускаться без доработок.

## Контекст

Учебное задание по дисциплине «Вычислительные системы». Нужно написать **кросс-платформенное десктопное приложение (Windows / Linux / macOS)** на **Python + PyQt6**, которое решает тяжёлую вычислительную задачу, распределяя её между несколькими компьютерами в локальной сети по схеме **Master–Slave**. Часть результата считает каждая машина, на главной машине (master) результаты собираются в полное решение. Приложение должно давать **явный выигрыш по времени** при работе на нескольких компьютерах. Целевой сценарий защиты: **4 компьютера**. Также приложение должно работать на одной машине (master и несколько slave-процессов на одном ПК).

## Задача для вычислений

**Численное вычисление тройного интеграла по параллелепипеду составной кубатурной формулой Симпсона на сетке N×N×N.**

- Область: `[ax, bx] × [ay, by] × [az, bz]`, N чётное, шаги `hx, hy, hz`.
- Формула: `I ≈ (hx·hy·hz / 27) · Σ wi·wj·wk · f(xi, yj, zk)`, где веса по каждой оси `1, 4, 2, 4, …, 2, 4, 1`.
- Две функции на выбор в интерфейсе:
  1. **Тестовая**: `f = sin(x)·cos(y)·exp(z)` (известен точный ответ, показывать абсолютную и относительную погрешность).
  2. **Тяжёлая** для замеров: дорогая функция, например `sin(x·y)·exp(-z) + sqrt(x² + y² + z² + 1)·cos(x + y·z) + log(1 + x·y·z)` на положительной области (подбери так, чтобы не было деления на ноль и NaN).
- Вычисления делай через **NumPy** (векторизация по слоям, чтобы не держать весь массив N³ в памяти: считать порциями слоёв по X).

## Ключевое требование к распределению

**Master не является только оркестратором: он тоже считает свою часть задачи одновременно со slave.** Распределение **статическое и происходит сразу при старте расчёта**, без очереди заданий:

1. Перед запуском в таблице узлов есть master (узел 0) и все подключённые slave.
2. Каждый узел при подключении сообщает число доступных ядер (`os.cpu_count()`).
3. При нажатии «Запустить» master делит диапазон по оси X на непрерывные слои **между всеми узлами, включая себя**. Размер доли пропорционален весу узла: вес = число ядер (в интерфейсе должен быть переключатель «равномерно / по числу ядер»). Деление должно быть корректным для простой кубатурной формулы Симпсона (границы слоёв согласованы с чётностью числа интервалов, веса на стыках учтены так, чтобы итоговая сумма совпала с последовательным расчётом).
4. Master отправляет каждому slave его диапазон и параметры задачи **одним сообщением**, после чего **сразу начинает считать свою долю** в отдельных процессах, параллельно со slave.
5. Каждый узел внутри себя использует **пул процессов** (`multiprocessing`) для загрузки всех своих ядер (из-за GIL потоки для вычислений не использовать).
6. Slave присылает master частичную сумму и время расчёта. Master суммирует все частичные результаты (включая свою) и показывает итог.
7. Опционально (если получится аккуратно, не усложняя код): если slave отключился или не ответил за таймаут, master пересчитывает его долю сам, а в логе показывается предупреждение.

## Сетевое взаимодействие

- **TCP-сокеты** (модуль `socket`), без сторонних сетевых библиотек.
- Формат сообщения: **4 байта длины (big-endian, `struct`) + JSON в UTF-8**.
- Корректное чтение ровно N байт в цикле (`recv` может вернуть меньше).
- Типы сообщений TCP: `REGISTER` (slave → master: имя, число ядер), `TASK` (master → slave: диапазон слоёв, N, границы области, функция), `PROGRESS` (slave → master: процент выполнения, по желанию), `RESULT` (slave → master: частичная сумма, время расчёта), `HEARTBEAT`, `SHUTDOWN`. Для автопоиска по UDP (отдельный сокет и порт): `DISCOVER` и `ANNOUNCE` (см. ниже).
- Master слушает TCP-порт (по умолчанию 5000), для каждого slave отдельный поток-обработчик. Slave подключается по IP и порту master.

### Автоматический поиск master в локальной сети (UDP)

Slave должен **сам находить master в сети**, вводить IP вручную не обязательно (ручной ввод остаётся как запасной вариант). Реализуй через **UDP-broadcast** на стандартном модуле `socket`, без сторонних библиотек:

1. **Master** при запуске (режим Master) открывает UDP-сокет на отдельном порту (по умолчанию 5001, `SO_REUSEADDR`) и слушает запросы поиска в отдельном потоке.
2. **Slave** по кнопке «Найти master» (а также автоматически при открытии окна Slave) отправляет широковещательный запрос `DISCOVER` (JSON: версия протокола, код группы) и в течение 2–3 секунд собирает ответы. Запрос повторяй 2–3 раза с небольшой паузой, т.к. UDP не гарантирует доставку.
3. **Master** в ответ присылает **unicast-ответом** отправителю сообщение `ANNOUNCE`: имя master, его IP, TCP-порт, текущее число подключённых slave, код группы.
4. Slave показывает найденные master в списке (имя, IP, порт, число подключённых узлов). Если найден ровно один, предложи подключиться к нему одним нажатием (или автоподключение, переключаемое чекбоксом «Подключаться автоматически к единственному найденному master»). Если найдено несколько, пользователь выбирает из списка.
5. После выбора slave подключается по TCP и проходит обычную регистрацию (`REGISTER`).

Детали реализации:
- **Код группы**: в окнах Master и Slave поле «Код группы» (по умолчанию, например, `lab`). Master отвечает только на запросы с совпадающим кодом, а slave показывает только master с тем же кодом. Это нужно, потому что в аудитории в одной сети могут одновременно работать мастера других групп, и нужно, чтобы slave не подключился к чужому.
- Отправляй запрос не только на `255.255.255.255`, но и на широковещательные адреса локальных интерфейсов (например, для каждого локального IPv4-адреса `x.y.z.255` для сети /24), так как на машинах с несколькими сетевыми адаптерами (Wi-Fi + Ethernet, VPN, Docker, виртуальные адаптеры) запрос на `255.255.255.255` может уйти не в ту сеть. Локальные адреса определяй стандартными средствами (`socket`), без дополнительных пакетов.
- Сокет slave: `SO_BROADCAST`, таймаут на приём; поиск выполняется **не в GUI-потоке** (`QThread`), результаты приходят через `pyqtSignal`.
- Master не должен падать, если UDP-порт занят: показать понятное сообщение в логе (автопоиск не работает, но ручное подключение по TCP работает).
- **Запасной вариант**: если ничего не найдено (UDP-broadcast часто блокируется в Wi-Fi-сетях с изоляцией клиентов, на некоторых роутерах и в файрволах), в окне Slave показать подсказку «Master не найден: проверьте, что компьютеры в одной сети и разрешён UDP-порт 5001, либо введите IP вручную» и оставить поля ручного ввода IP и порта.
- Лог в обоих окнах: когда получен запрос поиска, когда отправлен ответ, сколько master найдено.

## Интерфейс (PyQt6)

Одно приложение. Режим выбирается **только через стартовое окно с двумя кнопками**: «Запустить как Master» и «Запустить как Slave». Аргументы командной строки для выбора режима не нужны.

**Стартовое окно:** небольшое окно с заголовком приложения и двумя крупными кнопками. По нажатию на кнопку стартовое окно закрывается и открывается окно выбранной роли (окно Master или окно Slave). Роль выбирается один раз при запуске, переключаться между ролями внутри работающего приложения не нужно: чтобы сменить роль, приложение закрывают и запускают заново. На одном компьютере можно запустить несколько экземпляров приложения (один Master и несколько Slave), каждый со своим стартовым окном.

**Окно Master:**
- Параметры: функция (тестовая/тяжёлая), границы области, N, TCP-порт, UDP-порт автопоиска, код группы, режим деления («равномерно / по ядрам»).
- Поле **«Название серии»**: по умолчанию заполняется автоматически из параметров (`функция_N<значение>_<режим деления>`, например `heavy_N600_cores`) и обновляется при смене параметров, пока пользователь не изменил его вручную. Пользователь может переопределить название; оно сохраняется в CSV и определяет, какие запуски попадут на один график.
- Таблица узлов: имя, IP, ядра, доля (диапазон слоёв), статус, прогресс, время расчёта. Master присутствует в таблице как обычный узел.
- Общий прогресс-бар, лог событий, кнопки «Запустить расчёт», «Остановить».
- Результат: значение интеграла, общее время (wall-clock), для тестовой функции абсолютная и относительная погрешность.
- После завершения расчёта таблица итогов по узлам (см. раздел «Замеры времени»).

**Окно Slave:**
- Блок автопоиска: кнопка «Найти master», список найденных master (имя, IP, порт, число подключённых узлов), чекбокс автоподключения к единственному найденному, поле «Код группы».
- Запасной ручной ввод IP и порта master, кнопка «Подключиться», статус, текущая задача, прогресс, лог.

**Важно:** вся сеть и все вычисления выполняются вне GUI-потока (`QThread` / процессы), в интерфейс данные передаются через `pyqtSignal`. Окно не должно зависать.

## Замеры времени (после каждого расчёта)

Автоматического бенчмарка (автоматического прогона расчёта на 1, 2, 3, 4 узлах) **не нужно**: количество узлов я буду менять вручную (подключать и отключать slave) и запускать расчёт сам. Запуски одной конфигурации объединяются в «серию» для графиков (см. ниже).

После завершения каждого расчёта master показывает итоги:

- **Общее время расчёта** (wall-clock, от нажатия «Запустить» до получения последнего результата и сборки суммы).
- **Таблица по узлам**: имя, IP, число ядер, доля задачи (диапазон слоёв и процент от всей задачи), **время расчёта этого узла**. Master присутствует в таблице как обычный узел.
- Количество узлов, участвовавших в расчёте, а также параметры запуска (функция, N, режим деления), чтобы результаты разных запусков можно было сравнивать.
- Время каждого узла измеряй на самом узле (только вычисления, без сети) и присылай вместе с результатом. Общее время измеряет master.

### Сохранение результатов в CSV (встроено в master)

После **каждого** завершённого запуска master **сразу и автоматически** сохраняет результат в папку `runs/`: сначала собирает CSV, затем по этим CSV тут же строит графики (pandas + matplotlib) и сохраняет их картинками. Никаких кнопок для этого нажимать не нужно. Файлы должны быть удобны для дальнейшего анализа в pandas.

Папка `runs/` рядом с приложением (создавать автоматически, путь можно сменить в настройках master). В ней два накопительных CSV-файла:

1. `runs.csv`: **одна строка = один запуск**. Колонки: `run_id`, `timestamp` (ISO 8601), `function` (test/heavy), `N`, `split_mode` (equal/cores), `series`, `nodes_count`, `nodes_list` (имена узлов через `;`), `total_cores`, `total_time_s`, `integral_value`, `abs_error` и `rel_error` (для тестовой функции, иначе пусто), `status` (ok/stopped/failed).
2. `run_nodes.csv`: **одна строка = один узел в одном запуске**. Колонки: `run_id`, `node_name`, `ip`, `cores`, `slice_start`, `slice_end`, `share_percent`, `node_time_s`, `partial_sum`, `is_master` (true/false). Связь с `runs.csv` по `run_id`.

Требования к CSV:
- Запись с заголовком при создании файла и дозапись при следующих запусках (режим append), кодировка UTF-8, разделитель запятая, десятичная точка, время в секундах (float).
- `run_id` инкрементальный и продолжается после перезапуска программы (определяй по последней строке файла).
- Запись сразу после завершения расчёта (с `flush`), чтобы данные не терялись при закрытии программы.
- Если файл не удаётся открыть на запись (например, открыт в Excel на Windows), не ронять приложение: показать понятное сообщение в логе и сохранить запуск в запасной файл с суффиксом времени.
- В окне master кнопка «Открыть папку с результатами» и подпись с текущим путём.
- Запись CSV делай стандартным модулем `csv`; чтение для построения графиков через pandas.
- Остановленные и неудавшиеся запуски тоже записываются со своим `status`.

### Автоматические графики (после записи CSV)

Сразу после записи CSV master строит графики **из этих же файлов** (`pandas.read_csv`, затем `matplotlib`) и сохраняет их в PNG. Все исходные запуски остаются в CSV навсегда (ничего не удаляется и не перезаписывается), а графики строятся только по **серии текущего запуска** (колонка `series`).

**Правило выбора данных для графиков серии:**
- Берутся только запуски со `status = ok`.
- Для каждого значения `nodes_count` в серии используется **только последний запуск** (с наибольшим `run_id`). Повторные запуски с тем же числом узлов просто заменяют предыдущий результат на графиках (в CSV предыдущие остаются).
- Результат: на графике ровно одна точка на каждое число узлов, повторы не создают «кашу».
- Если внутри одной серии оказались запуски с разными `function`, `N` или `split_mode` (например, пользователь вручную дал одинаковое название), выведи в лог предупреждение, что графики серии могут быть некорректны.

**Что сохраняется** (папка серии `runs/series_<название>/`, название очищай от символов, недопустимых в именах файлов; файлы перезаписываются после каждого запуска серии):
1. `time_vs_nodes.png`: общее время расчёта (ось Y) от числа узлов (ось X), точки соединены линией, у каждой точки подпись со временем в секундах. В заголовке название серии, функция, N, режим деления.
2. `speedup_vs_nodes.png`: ускорение `S(n) = T(1) / T(n)`, где `T(1)` это время запуска на одном узле (только master) в этой серии, и идеальная линия `S = n` для сравнения. Если в серии нет запуска с одним узлом, график не строить, а в логе написать, что для ускорения нужен запуск только на master.
3. `efficiency_vs_nodes.png`: эффективность `E(n) = S(n) / n` (по желанию можно объединить с предыдущим графиком в одну картинку из двух панелей). Те же правила, что и для ускорения.
4. `summary.csv`: по строке на каждое число узлов: `nodes_count`, `run_id` (какой запуск использован), `nodes_list`, `total_cores`, `total_time_s`, `speedup`, `efficiency`. Удобно переносить в отчёт.
5. Отдельно для **каждого запуска** подпапка `runs/series_<название>/run_<id>/` с `nodes_time.png`: столбчатая диаграмма `node_time_s` по узлам этого запуска (master выделен цветом или подписью), в заголовке общее время и число узлов. По ней видно баланс загрузки узлов.

Требования к построению графиков:
- Использовать бэкенд matplotlib `Agg` (без окон), чтобы не конфликтовать с PyQt; никаких `plt.show()`.
- Графики строить **не в GUI-потоке** (отдельный `QThread`), по завершении отправить сигнал, а в лог master вывести путь к созданным файлам.
- Любая ошибка при построении графиков (например, нет pandas или matplotlib, мало данных) не должна ломать приложение или приводить к потере CSV: CSV пишется первым, а ошибка графиков только выводится в лог.
- Если данных для графика пока мало (например, один запуск), строить то, что возможно, без падения.

```
project/
├── common/
│   ├── protocol.py      # отправка/приём сообщений (длина + JSON)

│   ├── discovery.py     # UDP-автопоиск: ответчик в master, поиск в slave (DISCOVER / ANNOUNCE)

│   ├── server.py        # приём подключений, раздача долей, локальный расчёт, сборка результата
│   ├── results_store.py # запись результатов запусков в runs/runs.csv и runs/run_nodes.csv
│   ├── plots.py         # автоматические графики из CSV (pandas + matplotlib, бэкенд Agg)
│   └── gui_master.py
├── slave/
│   ├── client.py        # подключение, получение доли, расчёт, отправка результата
│   └── gui_slave.py
├── runs/                # создаётся автоматически: runs.csv, run_nodes.csv, series_<название>/ (графики, summary.csv, run_<id>/)
├── tests/               # проверка интегратора, протокола и записи CSV
├── main.py              # стартовое окно с кнопками «Master» / «Slave» и запуск выбранного окна
└── requirements.txt     # PyQt6, numpy, pandas, matplotlib
```

## Требования к коду

- Python 3.10+, кросс-платформенность: не использовать ничего специфичного для одной ОС; учесть `multiprocessing.freeze_support()` и запуск через `if __name__ == "__main__":` (важно для Windows и macOS).
- Тип-подсказки, docstring у основных функций, комментарии на русском.
